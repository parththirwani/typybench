# Paired repair of model-created type errors

This exploratory pilot uses the 90 caller-only parameter predictions frozen in `experiments/parameter_context/runs/holdout_20261019`. An annotation-only insertion placed 84 valid predictions into four copies of `repo_without_types`. With mypy run from each repository root and `--explicit-package-bases`, Sphinx has eight new `arg-type` diagnostics and Gradio has eleven. Source-only resolution and deduplication leave five Sphinx and four Gradio parameter repair sites. The selection files are `sphinx_derived_20261019/selected_v2.json` and `gradio_derived_20261019/selected_v2.json` under the error-to-context runs directory. These nine sites are fixed before correction calls.

For each site, both arms start from the same frozen derived baseline. Arm A gets the mypy error, a numbered call-site window, and the annotated parameter line to edit. Arm B gets the same system and user message plus one untyped source definition from `repo_without_types`. Neither arm sees the typed reference. Each makes one `gpt-5.4-mini` call at temperature zero and returns a one-line JSON patch. The validator rejects executable-code changes, imports, and edits outside the parameter site. Mypy runs in each isolated arm copy under the same command used for baseline selection. A clean correction removes the target error without increasing the total error count. Failures and invalid edits remain in the paired denominator.

The nine roots, not the nineteen correlated diagnostics, are the units of comparison. Report the paired table and token use. This pilot has little statistical power; a B-only example may establish feasibility but cannot establish a general retrieval benefit. Do not pool it with the earlier Typer and pre-commit pilots, which used different baseline generation and prompting.
